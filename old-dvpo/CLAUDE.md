# ai_project_v.piter — DPVO для бенчмарку SLAM на UCU SLAM Dataset

Особистий робочий репо Теодора (приватний, github.com/oToTak/ai_project_v.piter) у командному
проєкті «Бенчмаркінг SLAM на UCU SLAM Dataset». Тут — частина Теодора: **DPVO** (learning-based, mono).
Готовий код потім переноситься в спільний репо команди зі збереженням історії (CONVENTIONS.md §9).

## З чого почати

`tasks/README.md` — ціль поточного запуску, напрямки, типи сесій, правила.

## Жорсткі правила

- **CONVENTIONS.md — закон** (назви, формати, метрики, структура папок). Не змінювати.
  `CONVENTIONS.md` і `PLAN.md` — копії командних документів; джерело правди — спільний репо.
  Пропозиції змін — текстом для команди (в `tasks/inbox/`), не правкою файлу.
- **Працювати лише в цьому репо.** Інші репо автора й команди не читати й не змінювати.
  Публічні залежності (DPVO, ucu-slam-dataset) клонуються тільки всередині Colab-ноутбука.
- Дані, `.zip` з evo, ваги моделей, бінарники — не в git (`data/` у `.gitignore`).
- Токени HF/GitHub не просити, не зберігати, не вписувати в ноутбук — лише Colab Secrets.
- Комітити лише свої шляхи: `git add <шляхи>`, ніколи `-A` / `commit -a`; перед комітом `git diff --cached --stat`.
- Напівроботу за готову не видавати. Не вдалося — статус «блокер» з причиною.

## Середовище

- Mac автора: macOS 12.7, Intel i5 (2 ядра), 8 GB RAM, **без NVIDIA/CUDA** → DPVO локально не запускається.
- **GPU-робота — у Google Colab (T4).** Claude Colab не запускає: сесія готує ноутбук/команди,
  автор запускає і кладе результати (траєкторії, логи) у `results/...`.
- Локально (Mac): лише оцінка й графіки — `uv venv --python 3.12 ~/venvs/slam`, `evo==1.37.1` (CONVENTIONS.md §5).
- Shell: zsh. Команди з'єднувати `&&`.
