## Типи сесій

Кожна сесія — новий чат і один тип. Перше повідомлення — фраза-початок, напр.
«Реалізація: tasks/dpvo/02-run-wrapper».

| Тип | Коли | Вихід | Модель |
|---|---|---|---|
| Загальне планування | змінити ціль, напрямки, правила | цей файл, README напрямків | Opus |
| Планування напрямку | у напрямку ще немає завдань | папки завдань з `goal.md`, рядки DECISIONS | Opus |
| План завдання | з автором вирішити «що і як» | `spec.md` (≤ 2k токенів) | Opus / Sonnet-high |
| Реалізація | є `goal.md` (+ `spec.md`, якщо потрібен) | код, `impl.md`, коміт | Sonnet |
| Прогін і аналіз | код готовий; Colab запускає автор | `results/...`, `run.md`, висновок | Sonnet |
| Обслуговування | інбокс, LOG, порядок | порядок у `tasks/` | Sonnet |

Механічна робота за готовими правилами — Sonnet із середнім міркуванням. Кілька дрібних завдань
одного типу — один чат із `/compact` між ними.

## Правила для всіх сесій

1. Порядок читання: `tasks/README.md` → README свого напрямку → файли свого завдання.
   Чужі напрямки — лише за прямим посиланням. `CONVENTIONS.md` — розділи, на які посилається завдання.
2. Рішення автора — лише в `DECISIONS-1.md`. Записане не перепитувати. Питання автору — одне за раз;
   вибір — нумерованим меню прямо в повідомленні.
3. Реалізація читає `goal.md` («Готово, коли», «Межі»), `spec.md` і останні 5 рядків `LOG.md`.
4. `git diff --stat` не виходить за «Файли» з `spec.md` / «Межі» з `goal.md`.
5. Завершення сесії: рядок у `LOG.md` → коміт своїх шляхів → у чаті назвати наступну сесію
   (тип, модель, новий чат чи `/compact`).
6. Статус «закрито» — лише коли все з «Готово, коли» правда. Інакше «виконано» або «блокер: <причина>».
7. Довге — у файл, у чат — суть.

## Стандарт папок

```
tasks/README.md                 цей файл
tasks/<напрямок>/README.md      Мета · Готово, коли · Межі · Що відомо · Відкрите · Завдання
tasks/<напрямок>/<NN>-<назва>/
    goal.md                     Мета · Готово, коли · Межі · Читати · Питання автору   (планування)
    spec.md                     як саме робити, якщо потрібно                           (план завдання)
    impl.md                     що зроблено, відхилення, «Питання автору»               (реалізація)
    run.md                      як запускали, що вийшло, цифри                          (прогін)
tasks/LOG.md                    один рядок на сесію, ≤ 200 символів
tasks/DECISIONS-1.md            лише рішення автора: «дата · напрямок · рішення · чому»
tasks/inbox/                    вільні думки автора: «в інбокс: …» → <дата>-<коротко>.md
```

Номери завдань задають порядок виконання; вставки — літерами (`02a`).
Код живе там, де велить CONVENTIONS.md §2 (`docker/dpvo/`, `configs/dpvo/`, `scripts/dpvo/`, `results/dpvo/`).
