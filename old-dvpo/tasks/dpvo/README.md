# Напрямок dpvo

**Мета:** DPVO у Google Colab дає покадрові траєкторії у форматі CONVENTIONS.md §4 для TUM `fr1_xyz` і УКУ `seq01`.

**Готово, коли:**
- `results/dpvo/mono/tum/fr1_xyz/` і `results/dpvo/mono/ucu/seq01/` містять `traj_run1.txt` + `meta.yaml`;
- ATE на `fr1_xyz` близький до статті (порядок 1–2 см) або розбіжність пояснена;
- збірку й прогін можна відтворити з `docker/dpvo/` одним ноутбуком.

**Межі:** лише mono DPVO. Без Pangolin-в'юера, без DBoW2/класичного loop closure (DPV-SLAM — після midterm).
Не чіпати інші методи. Depth з УКУ не використовувати.

## Що відомо (перевірено в коді DPVO 21.10.2026, коміт `0ac95b6`)

- Потрібна CUDA. Офіційно: Ubuntu 20/22, CUDA 11/12, conda-env (torch 2.3.1, CUDA 12.1, numpy 1.26.4).
  У README DPVO є офіційний Colab-ноутбук — орієнтир.
- Встановлення: `eigen-3.4.0` у `thirdparty/`, потім `pip install .` (збирає CUDA-розширення, хвилини).
  Ваги — `models.zip` (Dropbox) зі скрипта `download_models_and_data.sh`; решту (~2 GB) не качати.
- **`demo.py` пише в траєкторію номери кадрів, а не час** → потрібна своя обгортка, що подає
  справжні таймстемпи з `rgb.txt` (так робить `evaluate_tum.py`: `queue.put((timestamp, image, intrinsics))`).
- `demo.py` за замовчуванням `--stride=2` → ставити `stride=1` (CONVENTIONS: поза для кожного кадру).
  `DPVO.terminate()` інтерполює пози для **всіх** поданих кадрів і повертає `x y z qx qy qz qw` + tstamps.
- Калібрування: файл з одним рядком `fx fy cx cy [k1 k2 p1 p2 …]`; якщо > 4 чисел — `cv2.undistort`.
  Кадр обрізається до кратного 16 (640×480 — без обрізання).
- УКУ (`calibration/calibration.yaml` репо датасету, radtan):
  `601.1733383650345 600.2663647399592 314.0164516341506 250.039444021504 0.139268662386042 -0.30741279731381366 0.0007272799549728076 0.0006655761403425819`
- TUM fr1 (як у `evaluate_tum.py`): `517.3 516.5 318.6 255.3`, дисторсія `0.2624 -0.9531 -0.0054 0.0026 1.1633`,
  після undistort обрізка 8 px зверху/знизу і 16 px з боків (cx −16, cy −8).
- `export_tum.py`: PNG з іменами = ціле число наносекунд; `rgb.txt` — `timestamp path` у секундах, рядок-заголовок з `#`.
  Потрібен Python ≥ 3.12. `sequence-1.mcap` = 6.5 GB.
- DPV-SLAM живе в тому самому репо DPVO (конфіг `LOOP_CLOSURE`) — збірка знадобиться після midterm.

## Відкрите

- Чи збереться DPVO з torch, що стоїть у Colab за замовчуванням, чи треба ставити torch 2.3.1/cu121.
- Скільки триває прогін seq01 (6532 кадри) на T4; чи вистачить пам'яті Colab для експорту 6.5 GB.
