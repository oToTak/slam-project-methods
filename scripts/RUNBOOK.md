# Як рахувати на обох ПК (один порядок для головного ПК і ПК брата)

Обидва ПК мають **той самий код** (GitHub `main`) і **ту саму кнопку** `START.bat`. Різниця лише в налаштуваннях ПК
(файл `~/.config/slam/runner.conf` у WSL): головний ПК (`TEODOR`) копає сиквенси 1→13, ПК брата (`StarDestroyer`) — 13→1, і бюджет диска для даних (`DATA_BUDGET_GB`).
`.mcap` не тримає жоден ПК: після сиквенсу дані видаляються. (Цифра ~1 ТБ «вільно», яку показує WSL, — це віртуальний розмір
WSL-диска, а не реальне місце; у брата реально вільно близько 130 ГБ, для нас дозволено 50–70, тож бюджет 60 ГБ.)

| Файл на робочому столі | Що робить |
|---|---|
| `START.bat` | **оновлює код, перевіряє встановлення, показує пораховане, рахує** (подвійний клік). Вікно не закривай |
| `STATUS.bat` | показує, де ми зараз (можна відкривати, коли черга працює) |

Обидва викликають у WSL `~/slam-runner/scripts/start.sh` (`STATUS.bat` — з `--status`).

## Що робить START.bat (по кроках, усе пише у вікні)
1. **Оновлення коду:** `git pull --ff-only` у `~/slam-runner` (окремий клон лише для рахування; у ньому ніхто не комітить).
   Нема мережі → `[warn]` і робота на поточному коді.
2. **Налаштування ПК** з `~/.config/slam/runner.conf`. Якщо файлу нема — два питання: «з початку (1) чи з кінця (13)?» і «скільки ГБ можна зайняти даними?».
3. **Перевірка встановлення** (`setup_all_really_all.sh --check`): для кожного методу з реєстру `scripts/queue/methods.conf` — встановлений чи ні.
   Нема → запускає рецепт `scripts/setup/<метод>.sh` (**може спитати sudo-пароль: вводиш сам**). Не встановився → `[warn]`, цього разу без нього.
   (`dpvslam` — це DPVO з loop closure: без sudo і без збірки, за потреби лише докидає python-пакети в `~/venvs/dpvo`.)
4. **Входи:** Hugging Face (якщо нема — просить увійти, токен вводиш сам), токен GitHub (без нього інший ПК не бачить твого прогресу).
5. **Що пораховано:** таблиця 13 сиквенсів.
6. **Рахує:** черга з твого кінця. Раз на 10 хв і в кінці надсилає прогрес у гілку `runner-<ім'я ПК>` на GitHub. ПК не засинає, поки йде робота.

Перевірити без запуску (кроки 1–5, нічого не ставить і не рахує): PowerShell → `wsl -d Ubuntu-22.04 -- bash ~/slam-runner/scripts/start.sh --check`.

## Перший раз (одноразовий перехід на `~/slam-runner`)
Робиться **між запусками**: якщо черга йде, дочекайся кінця прогону (`STATUS.bat`), тоді **один** Ctrl+C у вікні черги.
Нічого старого не видаляється: результати **копіюються** в `$DATA_ROOT/results`, старий каталог лишається як резерв.

**Головний ПК (`TEODOR`).** Токен GitHub у WSL (один раз, вводиш сам; fine-grained, лише цей репо, Contents: read+write):
```bash
cd /mnt/t/my_repos/slam-project-methods
bash scripts/report/push_status.sh --token
bash scripts/sync/migrate_to_git.sh --pc main
```
Розробка лишається в `T:\my_repos\slam-project-methods`; рахує тільки `~/slam-runner`. Результати воркера: `T:\slam-data\results`.
Код, який має доїхати до обох ПК, треба **закомітити й запушити в `main`** (лише після перевірки: брат підхопить його на наступному START).

**ПК брата (`StarDestroyer`).** Після того як Теодор запушив `main` з цим кодом. В Ubuntu (меню Пуск → «Ubuntu 22.04»), одна команда:
```bash
git clone -b main https://github.com/oToTak/slam-project-methods.git ~/slam-runner && bash ~/slam-runner/scripts/sync/migrate_to_git.sh --pc brother
```
(Репо публічне — перевірено 13.11.2026 — тож клон без токена. Токен для звітів уже лежить у `~/.config/slam/github_token`.
Якщо репо стане приватним, перед `git clone` додати `GIT_ASKPASS=~/.config/slam/git-askpass.sh `.) Скрипт:
перевіряє, що нічого не рахується → позначає клон → копіює `~/slam-local/results` у `~/slam-data/results` →
пише `runner.conf` (з 13 вниз, бюджет даних 60 ГБ, `.mcap` не тримати) → показує, що встановлено (нічого не ставить) →
кладе `START.bat` і `STATUS.bat` на робочий стіл і в `C:\calculator-dire` (якщо є); старі `START_SLAM.bat`/`STATUS_SLAM.bat` там стають `*.bat.old`.
Повторний запуск безпечний. Далі — подвійний клік `START.bat`.

Якщо скрипт пише «не знайшов робочого столу» — скопіюй `START.bat` і `STATUS.bat` з
`\\wsl$\Ubuntu-22.04\home\<linux-ім'я>\slam-runner\scripts\windows\` на робочий стіл руками.

## Старт
1. Подвійний клік `START.bat`. Якщо пише, що вже щось працює — другу копію не запускає, і це правильно.
2. Згорни вікно. Не закривай.

## Зупинка
**Один раз Ctrl+C** у вікні черги, зачекай (до 20 с), поки з'явиться «Черга зупинена». Потім можна вимикати ПК.
Далі знову `START.bat` — готове пропуститься, нічого не втрачається. Випадково закрив вікно — теж безпечно (зупиниться, як при Ctrl+C).

## Не роби, поки йде робота
`wsl --shutdown`, перезавантаження, вимкнення з розетки, закриття кришки ноутбука, ручні оновлення Windows.

## Межа між ПК
Воркер сам читає гілку іншого ПК і пропускає те, що там уже пораховано або в роботі (задача S1; **поки її не злито в `main`, цього нема**:
тоді ПК не бачать один одного, і межу ставлять руками). Аварійний важіль, коли інший ПК каже «я вже на seq08»:
```bash
wsl -d Ubuntu-22.04 --cd ~/slam-runner -- bash scripts/run_queue.sh --set-stop 8
```
Зняти: `--set-stop none`. START.bat попереджає, якщо межа стоїть.

## Налаштування ПК (`~/.config/slam/runner.conf`)
| Ключ | Значення |
|---|---|
| `START_AT` | `1` (головний ПК, вгору) або `13` (ПК брата, вниз) |
| `DATA_BUDGET_GB` | скільки ГБ дані в `$DATA_ROOT` можуть займати (брат: 60); сиквенс, що не влазить, воркер не бере. Порожньо = без ліміту. Рахуй від реального вільного місця у Windows, не від WSL |
| `KEEP_DATA` | `no` (обидва ПК) — видаляти `.mcap` й експорт після сиквенсу; `yes` — лише якщо реально є місце на всі 13 сиквенсів (6–20 ГБ `.mcap` кожен) |
| `RUNS` | прогонів на метод (3) |
| `METHODS` | `all` або список (`dpvo,orbslam3:mono_inertial`) |
| `REPORT_EVERY` | хвилин між звітами на GitHub (0 = вимкнено) |
Видалиш файл — START спитає знову.

## Якщо щось пішло не так
| Що бачиш | Що робити |
|---|---|
| «Уже щось працює» | Черга вже йде в іншому вікні, або залишок після аварії: зачекай 2 хв |
| «не вдалось оновити код» | Працює на старому коді, це не страшно. Якщо повторюється — скажи Теодору (мережа або токен) |
| «U WSL nema ~/slam-runner» (у вікні START.bat) | Не зроблено перехід: розділ «Перший раз» |
| просить sudo-пароль | Ставиться новий метод: пароль Linux-користувача (вводиш сам) |
| «X не встановився … цього разу без нього» | Інші методи рахуються. Скажи Теодору, надішли текст вище |
| «не залогінений у Hugging Face» | START сам попросить увійти; або PowerShell: `wsl -d Ubuntu-22.04` → `~/.local/bin/hf auth login` |
| «мало місця на диску», «не вміститься» | Звільни місце у Windows або (якщо Теодор дозволив) збільш `DATA_BUDGET_GB` у `runner.conf`, і знову START. `KEEP_DATA` має бути `no` |
| «ПОМИЛКА…», «ПЕРЕВІР», «поспіль із помилками» | Не перезапускай по колу. Напиши Теодору: він бачить кінець логу в GitHub-гілці |
| `Killed` / 137 | Не вистачило пам'яті: скажи Теодору |

## Що де лежить (у WSL)
| Шлях | Що |
|---|---|
| `~/slam-runner` | клон `main` для рахування (не редагувати руками: `git pull` має проходити) |
| `$DATA_ROOT/results` | результати воркера (`summary_<хост>.csv`, траєкторії); поза git, `git pull` їх не чіпає |
| `$DATA_ROOT/logs` | логи черги й методів, стан черги |
| `~/.config/slam/` | `github_token`, `runner.conf` (не в git) |
| `~/slam-report` | службовий клон для звітів у гілку `runner-<хост>` |
| `~/slam-local` (лише ПК брата) | старий код із bundle, резерв; нічого звідти не запускати |
`$DATA_ROOT`: головний ПК `/mnt/t/slam-data` (`T:\slam-data`), ПК брата `~/slam-data`.

## Коли все закінчено
1. Результати на GitHub (гілки `runner-*`, зведення `status/STATUS.md` у `main`) і локально в `$DATA_ROOT/results`.
2. На ПК брата: `~/.local/bin/hf auth logout`; `rm ~/.config/slam/github_token`; Теодор відкликає токен на сайті.
