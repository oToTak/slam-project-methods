# Покроковий алгоритм: налаштувати ПК для SLAM-прогонів (виконується разом із ChatGPT/іншою нейронкою)

Як користуватись: відкрий нейронку, встав їй **блок «Промпт для нейронки»** нижче, потім по одному давай кроки з розділів 1–5
(копіюй текст кроку цілком). Нейронка пояснює, що робити, ти виконуєш і вставляєш їй вивід команд.
Усі довгі команди — з цього файлу, їх не вигадувати.

## Промпт для нейронки (вставити першим повідомленням)

```
Ти допомагаєш мені, студенту, налаштувати ПК з Windows для запуску SLAM-методу (DPVO) у WSL2 Ubuntu 22.04
з NVIDIA GPU. Правила:
1. Говори українською, простими словами, без зайвої теорії.
2. Веди мене СТРОГО по кроках, які я тобі даю. По одному кроку за раз. Не вигадуй команд, яких нема в кроці;
   якщо мені треба щось інше — спершу запитай.
3. Для кожної команди скажи: де її запускати (PowerShell від адміністратора / PowerShell / термінал Ubuntu),
   що має з'явитись у кінці, і що надіслати тобі, якщо вийшла помилка.
4. Коли я вставляю вивід або помилку — розбери її і запропонуй мінімальне виправлення; не пропонуй видаляти файли,
   форматувати диски чи змінювати системні налаштування Windows без пояснення і мого підтвердження.
5. Ніколи не проси мене вставляти в чат паролі, токени (Hugging Face, GitHub) чи ключі. Токен я вводжу сам у термінал.
6. Якщо чогось не знаєш — скажи прямо, не вгадуй.
Почнемо, коли я дам перший крок.
```

## 0. Що ми робимо і навіщо (30 секунд)

- **Головний ПК** (`TEODOR`, GTX 1660 SUPER) — **уже налаштований**. Нічого ставити не треба: у розділі 1 лише перевірка.
- **ПК брата** (RTX 3060 12 GB) — ставимо з нуля. Код береться з GitHub (`git clone`, репо публічне); архіви й Google Диск більше не потрібні.
  Код живе в `~/slam-runner` (клон `main` лише для рахування) і сам оновлюється при кожному запуску `START.bat`.
  (Якщо ПК уже рахував зі старого архіву `~/slam-local` — не цей гайд, а розділ «Перший раз» у `scripts/RUNBOOK.md`.)
- Далі на ПК брата: Windows-частина (WSL, драйвер) → одна команда встановлення → вхід у Hugging Face → тест → повернення результатів.
- Усі дані (великі `.mcap`, 6–20 GB кожен) качаються з Hugging Face на кожному ПК окремо. Передавати їх між ПК не треба.

Що знадобиться: доступ до обох ПК; акаунт Hugging Face з прийнятими умовами датасету `ucu-autonomous-ugv/ucu-slam-dataset-v1`;
на ПК брата ≥ 60 GB вільного місця на диску, де буде WSL, і оновлений драйвер NVIDIA.

## 1. Головний ПК: перевірка (≈2 хв)

**Крок 1.1** — у PowerShell (звичайний):
```powershell
wsl -d Ubuntu-22.04
```
**Крок 1.2** — вже в Ubuntu:
```bash
cd /mnt/t/my_repos/slam-project-methods
bash scripts/setup/10_verify.sh
```
Очікую в кінці: `ALL OK`. Якщо є `[FAIL]` — надішли нейронці весь вивід.

**Крок 1.3 (рекомендовано, один раз) — дати WSL більше пам'яті.** Зараз WSL бачить лише 7.7 GB з 15.8 GB.
У Блокноті створи файл `C:\Users\tteod\.wslconfig` з таким вмістом (рядки точно такі):
```
[wsl2]
memory=11GB
processors=10
swap=16GB
swapFile=T:\\wsl\\swap.vhdx
```
Потім у PowerShell: `wsl --shutdown` (це зупиняє WSL; не роби цього, поки йде прогін). Знову відкрий Ubuntu — готово.

## 3. ПК брата: Windows-частина (≈20 хв + перезавантаження)

Виконується на ПК брата. Крок 3.0 — перевірки, без змін.

**Крок 3.0 — перевірити перед стартом** (PowerShell):
```powershell
winver
Get-PSDrive -PSProvider FileSystem | Select Name,@{n='FreeGB';e={[int]($_.Free/1GB)}}
nvidia-smi
```
Потрібно: Windows 10 22H2 / Windows 11; на диску для WSL ≥ 60 GB вільного; `nvidia-smi` показує RTX 3060.
Якщо `nvidia-smi` не працює — оновити драйвер NVIDIA з nvidia.com (рекомендований Game Ready/Studio) і перезавантажити.
Якщо в BIOS вимкнена віртуалізація (SVM/VT-x) — ввімкнути (нейронка підкаже для його материнки).

**Крок 3.1** — PowerShell **від імені адміністратора**:
```powershell
wsl --install -d Ubuntu-22.04
wsl --update
wsl --set-default-version 2
```
Перезавантажити ПК. Відкрити «Ubuntu 22.04» із меню Пуск, створити Linux-ім'я та пароль (запам'ятай пароль — він потрібен для `sudo`).

**Крок 3.2 (лише якщо на C: менше ~80 GB вільного)** — перенести WSL на інший диск, напр. `D:`. Попроси нейронку пояснити кожну команду
й не виконуй, поки не зрозумів. Скелет (PowerShell):
```powershell
wsl --shutdown
mkdir D:\wsl
wsl --export Ubuntu-22.04 D:\wsl\ubuntu-tmp.tar
wsl --unregister Ubuntu-22.04
wsl --import Ubuntu-22.04 D:\wsl\Ubuntu-22.04 D:\wsl\ubuntu-tmp.tar --version 2
```
Після `--import` вхід стає під `root`: у Ubuntu виконай `echo -e "[user]\ndefault=<твоє_linux_ім'я>" >> /etc/wsl.conf`, вийди й `wsl --shutdown`.
`--unregister` видаляє лише щойно встановлений порожній Ubuntu — на цьому свіжому ПК у ньому нічого цінного ще нема.

**Крок 3.3 — `.wslconfig`** (щоб збірка CUDA не падала через брак пам'яті). У Блокноті створи `C:\Users\<ім'я Windows>\.wslconfig`.
Постав `memory` ≈ 70 % ОЗП (мінімум 8GB), `processors` = кількість логічних ядер мінус 2, `swapFile` — шлях на диску з ≥ 16 GB. Приклад для 16 GB ОЗП/12 ядер:
```
[wsl2]
memory=11GB
processors=10
swap=16GB
swapFile=C:\\wsl-swap.vhdx
```
Далі PowerShell: `wsl --shutdown`. Відкрий Ubuntu знову.

**Крок 3.4 — перевірка GPU в Ubuntu**:
```bash
nvidia-smi
```
Має показати RTX 3060. Якщо ні — крок 3.0 (драйвер), потім `wsl --shutdown`.

## 4. ПК брата: встановлення (≈30–60 хв, більшість часу — завантаження й збірка)

Усе — в терміналі Ubuntu.

**Крок 4.1 — отримати код** (клон `main` у `~/slam-runner` + налаштування ПК «з 13 вниз, бюджет даних 60 ГБ» + `START.bat`/`STATUS.bat`
на робочий стіл; нічого не встановлює):
```bash
git clone -b main https://github.com/oToTak/slam-project-methods.git ~/slam-runner
bash ~/slam-runner/scripts/sync/migrate_to_git.sh --pc brother
```
Має закінчитись «Готово». `[missing] dpvo` на кроці 5/6 цього скрипта — нормально: його ставить крок 4.2.

**Крок 4.2 — одна команда встановлення (той самий скрипт і на головному ПК, і на ПК брата).** Попросить sudo-пароль
(той, що ти створив у кроці 3.1); повторний запуск безпечний:
```bash
cd ~/slam-runner
bash scripts/setup/setup_all_really_all.sh
```
Не закривай вікно. Скрипт сам: перевіряє пам'ять і місце → ставить усе (CUDA, evo, DPVO) → **попросить вхід у Hugging Face**
(токен ти вводиш руками, див. крок 5.1; на «add token as git credential?» — `n`) → перевіряє доступ до датасету → проганяє тести → показує план черги.
Якщо обірвалось — просто запусти ту саму команду ще раз. Логи: `~/slam-data/logs/setup_really_all_*.log` і `setup_all_*.log`.
Успіх = в кінці `ALL OK` (від `setup_all.sh`) і жодного рядка `[warn]`. Якщо `[FAIL]`, `[warn]` або помилка — надішли нейронці **останні ~40 рядків** виводу. Типові випадки:
`Killed`/137 — мало пам'яті (крок 3.3); `operation timed out` — повтори команду; `[warn] not logged in` — крок 5.2.

## 5. ПК брата: вхід у Hugging Face і приймальний тест

**Крок 5.1 — токен (створює людина, чий це акаунт Hugging Face; нейронці не показувати).** На huggingface.co в акаунті, де прийняті умови
датасету `ucu-autonomous-ugv/ucu-slam-dataset-v1`: Settings → Access Tokens → створити **fine-grained read-only** токен.
Найпростіше й безпечніше: брат створює **власний** акаунт HF, приймає умови датасету й робить токен у себе — тоді нічого не пересилається.
Якщо токен твій — вводь його сам, сидячи за ПК брата, а не пересилай у месенджері. Токен вводять руками в термінал на кроці 5.2.
Після завершення робіт токен видалити/відкликати на сайті.

**Крок 5.2 — логін** (зазвичай його вже запропонував скрипт з кроку 4.2; якщо ні або ти пропустив — тут. У терміналі Ubuntu; на питання «add token as git credential?» відповісти `n`):
```bash
~/.local/bin/hf auth login
~/.local/bin/hf auth whoami
```
`whoami` має показати акаунт.

**Крок 5.3 — приймальний тест (необов'язковий окремо: перший же сиквенс черги з розділу 6 теж його покаже; але якщо хочеш перевірити окремо)** (качає seq01, 6.5 GB; потім DPVO; на RTX 3060 швидкість ще не виміряна, на 1660 SUPER було 88 хв):
```bash
cd ~/slam-runner
bash scripts/accept_seq01.sh
```
В кінці буде `ACCEPTED` або `NOT ACCEPTED`. **Це не обов'язково помилка:** DPVO недетермінований, на головному ПК три однакові прогони дали
ATE 1.372 / 2.272 / 1.738 м (очікування 2.34 ± 0.30). Головне — `coverage 1.0`, `tracking_lost false`, ATE у межах 1–3 м. Якщо вийшло
NOT ACCEPTED, запусти ще раз `bash scripts/dpvo/run.sh ucu seq01` (2 рази) і порівняй числа в `~/slam-data/results/summary.csv`.
Помилка/зупинка до кінця прогону — надішли нейронці вивід.

**Крок 5.4 — результати** самі їдуть на GitHub (гілка `runner-<ім'я ПК>`, раз на 10 хв і в кінці). Для цього потрібен GitHub-токен
(один раз, вводиш сам): `bash ~/slam-runner/scripts/report/push_status.sh --token`. Локально результати в `~/slam-data/results`
(`summary_<хост>.csv`, `summary_extra_<хост>.csv`, `dpvo/`), таймінги завантажень — `~/slam-data/logs/fetch_timings.csv`.

**Крок 5.5 — прибрати доступ** (коли закінчили на чужому ПК):
```bash
~/.local/bin/hf auth logout
```

## 6. Запуск черги сиквенсів (обидва ПК, той самий алгоритм, різні кінці)

Ідея: усього 13 сиквенсів. Головний ПК бере їх **з початку** (1, 2, 3…), ПК брата — **з кінця** (13, 12, 11…). Коли зійдуться посередині — стоп.
Програма сама: качає один сиквенс → рахує його → записує результат → видаляє великі файли → бере наступний. Нічого рахувати вручну не треба.

**Крок 6.1 — запустити.** Подвійний клік `START.bat` на робочому столі (той самий файл на обох ПК). Вікно не закривай.
Він сам: оновлює код (`git pull`) → читає налаштування ПК (`~/.config/slam/runner.conf`: напрям 1→13 чи 13→1, бюджет диска `DATA_BUDGET_GB`) →
перевіряє встановлення методів (чого нема — ставить; sudo-пароль вводиш сам) → вхід у Hugging Face → показує пораховане → рахує
усі встановлені методи по 3 прогони. Подробиці й таблиця помилок — `scripts/RUNBOOK.md`.
Перевірити без запуску (нічого не ставить і не рахує): `bash ~/slam-runner/scripts/start.sh --check`.

**Крок 6.2 — перервати і продовжити.** Зупинити: `Ctrl-C` **один раз** і почекати (готові прогони лишаться, незавершений викинеться).
Продовжити: знову `START.bat` — готове пропуститься.

**Крок 6.3 — де я.** `STATUS.bat` (воркер не зупиняючи), або в Ubuntu `bash ~/slam-runner/scripts/start.sh --status`.
Він показує таблицю з 13 рядків і два рядки внизу: **«Ти тут: N»** і **«Готово підряд від твого кінця: …»**. Це число одне ПК повідомляє іншому (Теодор і брат питають один одного).

**Крок 6.4 — межа зустрічі.** Коли знаєш, де інший ПК (наприклад, він уже на seq08), на **своєму** ПК виставляєш:
```bash
bash ~/slam-runner/scripts/run_queue.sh --set-stop 8
```
Це означає «seq08 і далі в мій бік руху не братиму». Працює навіть поки воркер рахує: він перечитує межу перед кожним прогоном і зупиниться сам.
Зняти межу: `bash ~/slam-runner/scripts/run_queue.sh --set-stop none`. (Це аварійний важіль: коли воркер читатиме гілку іншого ПК — задача S1 —
зайняте іншим ПК пропускатиметься саме.)

**Крок 6.5 — що означають повідомлення.**
| Побачив | Що це |
|---|---|
| `мало місця на диску даних` | звільни місце (нічого не видаляється автоматично) і знову `START.bat` |
| `не залогінений у Hugging Face` | `~/.local/bin/hf auth login` (токен вводиш сам), потім знову `START.bat` |
| `завантаження/експорт … не вдалось` | інтернет або HF; повторний запуск докачає |
| `ПОМИЛКА: … завершився з кодом …` | прогін упав; дані цього сиквенсу лишились; надішли нейронці кінець логу (`~/slam-data/logs/queue_*_seqNN_*.log`) |
| `ПЕРЕВІР` у статусі | прогін закінчився, але поз менше, ніж кадрів; не повторювати наосліп — показати Теодору |
| `… поспіль із помилками` | черга сама зупинилась: схоже на проблему середовища (GPU, пам'ять); не крути в колі |

Скільки триває: seq01 на GTX 1660 SUPER виміряно 88 хв за прогін; довші сиквенси — пропорційно довше (це оцінка). Швидкість RTX 3060 ще не виміряна — її і покаже перший сиквенс.
Результати тим часом самі їдуть на GitHub (крок 5.4).
