## 4. Decision: ROS-free build + own tiny driver (not ROS 2 + bag replay)

Sources: https://docs.openvins.com/gs-installing-free.html (ROS-free build, `-DENABLE_ROS=OFF`, "limited support"), https://docs.openvins.com/gs-installing.html, https://github.com/rpng/open_vins.

Why: the ROS 2 path needs Humble (a large apt repository + sudo steps), a conversion of our TUM-style dataset (`rgb.txt`, `imu.txt`) to a bag/mcap, colcon, and real-time replay plumbing. The ROS-free path needs only 10 ordinary apt packages, and `ov_core` + `ov_init` are compiled into `libov_msckf_lib.so` by `ov_msckf`'s own CMake, so nothing is installed system-wide. Our driver (`scripts/openvins/driver/ov_ucu_driver.cc`) reads `rgb.txt` + the cleaned IMU file, feeds IMU and images in time order as fast as the filter runs (no sleeps), and writes one pose per processed frame. Cost: we depend on the library API of the pinned commit (`d0075dd`), not on a stable ROS interface.

## 5. Build steps (exact commands)

```
bash scripts/openvins/run_tests.sh            # bash -n + python stub tests, seconds, CPU
bash scripts/setup/openvins.sh --apt-only     # (or the sudo command above); skips itself if all packages are present
bash scripts/setup/openvins.sh --no-apt       # sources @d0075dd, libov_msckf_lib (cmake -DENABLE_ROS=OFF -DENABLE_ARUCO_TAGS=OFF), ov_ucu_driver
bash scripts/setup/openvins.sh --check        # exit 0 = driver + lib + pinned sources + no missing .so
# configs (already committed; regenerate/check):
python scripts/openvins/make_config.py --check
# sanity on EuRoC (cam0 only, made by scripts/orbslam3/euroc_to_tum.py):
bash scripts/openvins/run.sh euroc MH_01_easy --run 1
# real run (what the queue will call):
bash scripts/openvins/run.sh ucu seq01 --run 1
```

Build time and RAM: the Ceres/Eigen templates need about 2 GB per compile job; the recipe picks `min(cores, free GB / 2)` jobs, runs niced (`OV_JOBS`, `OV_NICE` override). Sources and build tree: `~/src/open_vins`; driver: `~/opt/openvins/bin/ov_ucu_driver`.

Output: `results/openvins/mono_inertial/<dataset>/<seq>/traj_run<R>.txt` (TUM, ONE LINE PER FRAME THAT HAS A POSE) + `meta.yaml`. Work files: `$DATA_ROOT/openvins_work/...`.

## 6. What the configs contain (and where each number comes from)

- `configs/openvins/ucu/{estimator_config,kalibr_imu_chain,kalibr_imucam_chain}.yaml`, generated by `scripts/openvins/make_config.py` from `configs/orbslam3/ucu_calib.json`, using the SAME Kalibr T_ic derivation as the ORB-SLAM3 settings (`scripts/orbslam3/make_settings.t_b_c`).
- `T_imu_cam` (camera to IMU) is the inverse of the dataset's `T_cam_imu`; the dataset's own "T_base_color" naming is inverted, which is exactly the trap handled in the ORB3 work. Time shift is 0 because the exporter already applied it.
- Estimator parameters = upstream EuRoC values with `max_cameras: 1`, `use_stereo: false`, `num_opencv_threads: 0`; IMU noise from the dataset calibration (not inflated). Not tuned per sequence.
- Output frame: the driver writes the IMU pose in the global frame and T_I_C; the post-processing composes `T_G_C = T_G_I * T_I_C` (JPL quaternions go through `quat_2_Rot`; Hamilton output in the file). For EuRoC the IMU (body) pose is evaluated (`--body-frame`), as in the EuRoC ground truth.

## 7. Honest gaps

The filter needs an initialisation phase (at least about 2 s of data), so the first frames have no pose. Nothing is interpolated or invented; coverage (time-span) and the frame share are in meta notes. `POSE_TOL=0.98` in `run_queue.py` will therefore very likely mark OpenVINS runs as `.bad_run` (the first seconds can never be posed): the lead must decide on a per-method tolerance or on an evaluation over the posed span.
